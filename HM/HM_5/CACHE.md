# Кэширование в проекте

## 1. Общая информация

В проекте реализовано кэширование с помощью встроенного механизма Django Cache Framework.

Для хранения кэшированных данных используется `LocMemCache`. Это локальный кэш, который хранит данные в памяти приложения.

Основные настройки находятся в файле `config/settings.py`:

```python
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.locmem.LocMemCache',
        'LOCATION': 'news-cache',
        'TIMEOUT': 300,
    }
}
```

Время хранения данных по умолчанию составляет 300 секунд (5 минут).

## 2. Кэширование списка новостей

Для кэширования списка новостей используется декоратор `cache_page`.

Он применяется к классу `NewsListView` с помощью `method_decorator`:

```python
@method_decorator(cache_page(60 * 5), name='dispatch')
class NewsListView(ListView):
    ...
```

Таким образом, результат обработки страницы со списком новостей сохраняется в кэше на 5 минут.

При повторном обращении к странице Django использует сохранённый результат, что позволяет уменьшить количество обращений к базе данных и ускорить загрузку страницы.

## 3. Кэширование детальной страницы новости

Для отдельной новости используется низкоуровневый API кеширования Django: `cache.get()` и `cache.set()`.

В качестве ключа используется идентификатор новости и идентификатор пользователя:

```python
cache_key = f'news_detail_{slug}_user_{user_id}'
```

Это позволяет хранить отдельные варианты кэша для разных пользователей.

Если данные отсутствуют в кэше, Django получает новость из базы данных и сохраняет её на 300 секунд.

## 4. Кэширование категорий

В файле `news/cache_utils.py` реализованы две функции:

- `get_categories()` — получает список категорий и сохраняет его в кэше.
- `get_news_count_by_category()` — получает количество новостей в каждой категории и сохраняет результат.

Для получения данных используются методы `cache.get()` и `cache.set()`.

Это позволяет не выполнять повторные SQL-запросы при каждом обращении к списку категорий и количеству новостей.

## 5. Очистка кэша

Для предотвращения отображения устаревшей информации реализована автоматическая очистка кэша с помощью сигналов Django.

В файле `news/signals.py` используются:

- `post_save` — срабатывает после создания или обновления новости.
- `post_delete` — срабатывает после удаления новости.

При срабатывании любого из сигналов вызывается функция `clear_news_cache()`, которая очищает кэш.

```python
def clear_news_cache():
    cache.clear()
```

Сигналы подключаются автоматически через метод `ready()` в файле `news/apps.py`.

## 6. Результаты проверки кэширования

Для проверки эффективности кэширования использовались `CaptureQueriesContext` и тестовый клиент Django `Client`.

Сначала кэш был очищен. Затем выполнено два последовательных GET-запроса к странице `/news/`.

Результаты проверки:

| Показатель | Первый запрос | Второй запрос |
|---|---:|---:|
| HTTP-статус | 200 | 200 |
| Количество SQL-запросов | 3 | 0 |
| Время выполнения | 21,78 мс | 3,44 мс |

На первом запросе Django обратился к базе данных и получил необходимые данные. После этого результат был сохранён в кэше.

При повторном запросе Django использовал сохранённую страницу, поэтому обращения к базе данных не потребовались.

## 7. Вывод

В результате реализации кэширования удалось сократить количество SQL-запросов при повторном обращении к странице списка новостей с 3 до 0.

Время выполнения запроса уменьшилось с 21,78 мс до 3,44 мс.

Таким образом, использование механизмов кэширования Django позволяет снизить нагрузку на базу данных, ускорить обработку повторных запросов и повысить производительность приложения.
